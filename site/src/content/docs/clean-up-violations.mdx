---
title: Clean up violations
description: Lower or remove recorded ceilings as the source tree improves.
---

import { TabItem, Tabs } from "@astrojs/starlight/components";

After reducing a violation, update the ratchet to preserve the improvement.

Read the failure. Note the path, measurement, configured limit, and ratchet ceiling. Split an
oversized file, reorganize a directory with too many files, correct an unexpected classification,
or adjust a limit only when the policy itself is wrong.

Preview the ratchet change for the affected path:

<Tabs syncKey="package-manager">
  <TabItem label="Cargo">

```sh
sprawl-guard ratchet path/to/improved/source
```

  </TabItem>
  <TabItem label="npm">

```sh
npm exec -- sprawl-guard ratchet path/to/improved/source
```

  </TabItem>
  <TabItem label="pnpm">

```sh
pnpm exec sprawl-guard ratchet path/to/improved/source
```

  </TabItem>
</Tabs>

Review the preview. If the measurement is still above its configured limit, its ceiling should
decrease to the new measurement. If it now satisfies the limit or is no longer measured, its entry
should disappear.

Write the reviewed change and recheck the repository:

<Tabs syncKey="package-manager">
  <TabItem label="Cargo">

```sh
sprawl-guard ratchet path/to/improved/source --write
sprawl-guard check
```

  </TabItem>
  <TabItem label="npm">

```sh
npm exec -- sprawl-guard ratchet path/to/improved/source --write
npm exec -- sprawl-guard check
```

  </TabItem>
  <TabItem label="pnpm">

```sh
pnpm exec sprawl-guard ratchet path/to/improved/source --write
pnpm exec sprawl-guard check
```

  </TabItem>
</Tabs>

Commit the code and ratchet change together. The updated ratchet prevents the violation from
returning to its previous size.

If the preview is surprising, use `sprawl-guard explain PATH` and
`sprawl-guard config resolved`, then consult
[how checks work](/sprawl-guard/reference/how-checks-work/).
