---
title: Clean up violations
description: Lower or remove recorded ceilings as the source tree improves.
---

import { Steps } from "@astrojs/starlight/components";

After reducing a violation, record the improvement in the ratchet file.

The commands below use `sprawl-guard` directly. For a project-local Node dependency, run them
through `npm exec -- sprawl-guard` or `pnpm exec sprawl-guard` instead.

<Steps>

1. Improve the source tree.

   Read the failure and note the path, measurement, limit, and ceiling. Split an oversized file,
   reorganize a directory with too many files, or fix an unexpected exclude or test glob. Change a
   limit only when the limit itself is wrong.

2. Preview the ratchet changes.

   ```sh
   sprawl-guard tighten
   ```

   When a measurement is still above its limit, `tighten` lowers its ceiling to the new measurement. When it
   is at or below the limit, or no longer measured, the entry is removed. Pass paths to tighten
   only those entries.

3. Write the changes and check the repository.

   ```sh title="Record improvements and check"
   sprawl-guard tighten --write
   sprawl-guard config upgrade --check
   sprawl-guard check
   ```

   Commit the source and ratchet changes together. With the lower ceiling, `check` fails if the violation grows back.

</Steps>

If the preview is surprising, run `sprawl-guard explain PATH` and `sprawl-guard config resolved`,
then see [how checks work](/sprawl-guard/reference/how-checks-work/).

Repositories that use the optional
[preparation recipe](/sprawl-guard/check-staged-changes/#prepare-improvements-locally) can run
`just sprawl-guard-prepare` instead of steps 2 and 3.
