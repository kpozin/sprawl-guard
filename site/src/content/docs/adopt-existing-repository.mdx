---
title: Adopt Sprawl Guard in an existing repository
description: Record existing violations without allowing them to grow.
---

import { Steps } from "@astrojs/starlight/components";

You can adopt Sprawl Guard without first fixing every file or directory that exceeds the desired
limits.

Adoption uses two files with different jobs. `sprawl-guard.toml` defines the policy. A second file
records current measurements that exceed that policy so they may remain temporarily but cannot
grow. Sprawl Guard calls this second file the ratchet.

The commands below use `sprawl-guard` directly. For a project-local Node dependency, run them
through `npm exec -- sprawl-guard` or `pnpm exec sprawl-guard` instead.

<Steps>

1. Create the policy configuration.

   Preview the generated configuration, then create `sprawl-guard.toml`:

   ```sh
   sprawl-guard init --dry-run
   sprawl-guard init
   ```

   Edit the generated file to [set the desired limits](/sprawl-guard/configure-checks/), not the repository's current maxima. Use `sprawl-guard config resolved` to review the complete policy.

2. Record existing violations.

   After setting the policy, preview the proposed ratchet before writing it:

   ```sh
   sprawl-guard baseline --all
   sprawl-guard baseline --all --write
   sprawl-guard check
   ```

   A preview with one file ceiling and one directory ceiling looks like:

   ```toml title="sprawl-guard.ratchet.toml"
   schema_version = 1

   [[files]]
   path = "src/large.py"
   role = "production"
   max_loc = 430

   [[directories]]
   path = "src/flat"
   role = "production"
   group = "source"
   leaf_files = 12
   ```

   File entries are identified by path and role. Directory entries are identified by path, role, and language group. The ratchet stores measured ceilings, not configuration limits or justifications.

3. Review and commit both files.

   The write creates the ratchet file selected by `[ratchet].file` in `sprawl-guard.toml`. Its default path is `sprawl-guard.ratchet.toml`. Review every entry. Each should cover maintained code that is expected to improve. Exclude generated or third-party code, and use a documented override for a deliberate long-term exception.

   If a ratchet file already exists, `--all` replaces it. A replacement that would raise a ceiling is refused unless you add `--allow-raises`; review any increase carefully. Use path arguments instead of `--all` to replace only selected files or directories.

   Commit `sprawl-guard.toml` and `sprawl-guard.ratchet.toml` together. Confirm that the unchanged tree passes. Then temporarily increase one baselined measurement to verify that the ratchet rejects growth.

</Steps>
