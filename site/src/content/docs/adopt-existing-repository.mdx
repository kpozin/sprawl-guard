---
title: Adopt Sprawl Guard in an existing repository
description: Record existing violations without allowing them to grow.
---

import { Steps } from "@astrojs/starlight/components";

You can adopt Sprawl Guard without first fixing every file or directory that exceeds the limits you
want. `sprawl-guard.toml` sets the limits. The ratchet file, `sprawl-guard.ratchet.toml`, records
existing violations so they can shrink but not grow.

The commands below use `sprawl-guard` directly. For a project-local Node dependency, run them
through `npm exec -- sprawl-guard` or `pnpm exec sprawl-guard` instead.

<Steps>

1. Create the configuration.

   ```sh
   sprawl-guard init --write
   ```

   Edit `sprawl-guard.toml` to [set the limits you want](/sprawl-guard/configure-checks/), not the
   repository's current maxima. `sprawl-guard config resolved` shows the full configuration.

2. Preview the ratchet entries.

   ```sh
   sprawl-guard update
   ```

   ```text
   Ratchet changes:
   + add src/large.py (production lines): none -> 430
   + add src/flat (production direct files, group source): none -> 12

   Preview only; use --write to apply.
   ```

   Keep entries only for maintained code that is expected to improve. Exclude generated or
   third-party code, and use a documented override for a deliberate long-term exception.

3. Write the ratchet file.

   ```sh
   sprawl-guard update --write
   ```

   ```toml title="sprawl-guard.ratchet.toml"
   #:schema https://kpozin.github.io/sprawl-guard/schemas/v1/sprawl-guard.ratchet.schema.json
   schema_version = 1

   [[files]]
   path = "src/large.py"
   role = "production"
   max_lines = 430

   [[directories]]
   path = "src/flat"
   role = "production"
   group = "source"
   max_direct_files = 12
   ```

   Each entry stores only a ceiling. Limits stay in `sprawl-guard.toml`.

4. Check the repository.

   ```sh
   sprawl-guard check
   ```

   ```text
   Configuration: sprawl-guard.toml

   No sprawl-guard violations found.
   Checked 14 source files in 2 directories across 1 language.
   Passed with 2 ratchet entries remaining.
   ```

5. Commit `sprawl-guard.toml` and `sprawl-guard.ratchet.toml` together.

</Steps>

## Approve later exceptions

To record a new violation, preview `sprawl-guard update PATH`, review the added entries, then repeat
with `--write`. To let an existing violation grow, pass `--allow-increases` to both the preview and
the write; raised ceilings are marked `! raise`.

For a permanent exception, use a narrow
[`[[overrides]]` entry](/sprawl-guard/configure-checks/) with a reason. `update` never lowers or
removes ceilings; [`tighten`](/sprawl-guard/clean-up-violations/) does.

Run `check` on the whole repository after an approval, and commit the source and ratchet changes
together.
