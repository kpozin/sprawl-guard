This optional workflow checks the files staged for a commit instead of the working tree. Most
repositories need only the [CI job](/sprawl-guard/run-in-ci/).

## Prepare improvements locally

These optional Just recipes record improvements and then run the full check:

```just title="justfile"
sprawl-guard:
    sprawl-guard config upgrade --check --root "{{justfile_directory()}}" --config sprawl-guard.toml
    sprawl-guard check --root "{{justfile_directory()}}" --config sprawl-guard.toml

sprawl-guard-prepare:
    sprawl-guard tighten --write --root "{{justfile_directory()}}" --config sprawl-guard.toml
    just --justfile "{{justfile()}}" sprawl-guard

sprawl-guard-prepare-commit:
    python3 "{{justfile_directory()}}/scripts/sprawl-guard-commit.py" prepare -- sprawl-guard
```

For a project-local Node dependency, replace `sprawl-guard` in these recipes with
`npm exec -- sprawl-guard` or `pnpm exec sprawl-guard`.

Commit a ratchet file, even an empty one, before using them. A missing or invalid ratchet file is
an error; `sprawl-guard-prepare` does not create one or record new violations.

`sprawl-guard-prepare` reads the working tree, not the Git index. It lowers or removes existing
ceilings, then runs the full check. The check still fails on new violations and growth. If the check
fails, the lowered ceilings stay in the working tree for review. Nothing is rolled back or staged.

## Add a commit hook

The following Git hook runs `sprawl-guard-prepare-commit` for every commit, including deletion-only
commits. It checks a temporary copy of the staged files, so unstaged edits,
untracked files, local ignore rules, sparse checkouts, and checkout filters cannot affect it. It
always checks the whole repository.

Copy [the snapshot helper](/sprawl-guard/examples/prepare_commit.py) to
`scripts/sprawl-guard-commit.py` and commit it. It requires Python 3.11 or later and Git. For a
project-local dependency, replace the command after `--` with `npm exec -- sprawl-guard` or
`pnpm exec sprawl-guard`; the package manager runs from the original repository.

The helper has these limits:

- It supports regular staged files only, and refuses symlinks and submodules, including a symlinked
  config file or ratchet file.
- It refuses filenames the local filesystem cannot preserve exactly.
- It copies every regular staged file, including excluded files, to temporary storage, so disk use
  and copy time grow with the whole staged tree.
- It copies Git LFS files as committed pointers, without clean or smudge filters.

<Steps>

1. Save this hook and commit it alongside the recipes:

   ```sh title=".githooks/pre-commit"
   #!/bin/sh
   exec just sprawl-guard-prepare-commit
   ```

2. Enable it in your local checkout:

   ```sh
   chmod +x .githooks/pre-commit
   git config --local core.hooksPath .githooks
   ```

   If the repository already manages hooks, add the recipe there instead of replacing its hook
   directory.

3. Stage the source changes and commit. If tightening changes the ratchet file, the hook stops
   without changing the index. Review and stage the ratchet file, then retry. If the ratchet file is unchanged, the hook lets the commit proceed, unless the check fails.

</Steps>

Only the staged ignore files, config file, and ratchet file are used.

The hook copies a changed ratchet file back only if the working-tree copy still matches the staged
one, and it never changes the index. If the staged configuration is missing or invalid, the hook
fails before copying anything back. Avoid editing the index or the ratchet file while the hook runs.
If the index changes during the check, commit again.

For a read-only hook instead, use `just sprawl-guard`. With a hook manager such as pre-commit,
disable filename forwarding and run on deletion-only commits:

```yaml title=".pre-commit-config.yaml"
repos:
  - repo: local
    hooks:
      - id: sprawl-guard
        name: Sprawl Guard
        entry: just sprawl-guard
        language: system
        always_run: true
        pass_filenames: false
```

## Check the same snapshot in CI

To check the same staged snapshot in CI, commit the snapshot helper even if you do not enable the
hook, and run its read-only `check` action:

<Tabs syncKey="package-manager">
  <TabItem label="Cargo">

```yaml title=".github/workflows/sprawl-guard.yml"
name: Sprawl Guard

on: [pull_request, push]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo install sprawl-guard --version <VERSION> --locked
      - run: python3 scripts/sprawl-guard-commit.py check -- sprawl-guard
```

  </TabItem>
  <TabItem label="npm">

```yaml title=".github/workflows/sprawl-guard.yml"
name: Sprawl Guard

on: [pull_request, push]

permissions:
  contents: read

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-node@v6
        with:
          node-version: 22
      - run: npm ci
      - run: python3 scripts/sprawl-guard-commit.py check -- npm exec -- sprawl-guard
```

  </TabItem>

```yaml title=".github/workflows/sprawl-guard.yml"

        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: python3 scripts/sprawl-guard-commit.py check -- pnpm exec sprawl-guard
```
