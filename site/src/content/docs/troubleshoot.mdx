## The executable was not found

Check the installation for your package manager:

## Configuration is missing or invalid

Sprawl Guard uses built-in defaults when `sprawl-guard.toml` does not exist in the repository root.
Run `sprawl-guard init` to preview a configuration. Alternative filenames are not discovered. Select
one with `--config PATH`. Unknown fields are errors, and the message names the file and location.

## No files were checked, or the check passed unexpectedly

Run `sprawl-guard languages --detected`, then inspect enabled languages, global excludes, ignore
settings, and language globs in `sprawl-guard config resolved`. `sprawl-guard explain PATH` reports
the first rule that included or excluded a path.

## A path has the wrong language, test status, or override

Use `sprawl-guard explain PATH`. It reports which language claims the path, whether it is a test
file, its limits, matching overrides, and Rust `cfg(test)` handling. A path that more than one
enabled language claims is an error. When several overrides match a path, later ones win for the
fields they set.

## A ratchet entry is stale, missing, or conflicted

A stale entry means that a measurement shrank, disappeared, or no longer exceeds its limit. Preview
`sprawl-guard tighten PATH`, then save it with `sprawl-guard tighten PATH --write`.

If a current violation has no entry, preview `sprawl-guard update PATH`, then save it with
`sprawl-guard update PATH --write`.

After concurrent edits, update your checkout, then rerun `update` or `tighten` on the affected
paths. Never resolve a
ratchet conflict by keeping an unexplained higher ceiling.

## Local and CI results differ

Compare the output of `sprawl-guard --version`, checkout contents, repository root, configuration
path, resolved configuration, and command line. Run `sprawl-guard check` in CI on the whole
repository. Ignore files and `[traversal]` settings can also change which files are scanned.

## JSON or SARIF is rejected

Confirm that `--format json` or `--format sarif` follows `check`. Only `check` supports SARIF.
`languages` and `explain` support `human` and `json`, and `update` and `tighten` support `human` and
`toml`. Check the exit code before parsing stdout. When a path cannot be read, `check --format json`
still prints a JSON report and exits `2`. For other errors, Sprawl Guard prints a message on stderr
and may leave stdout empty. SARIF output is version 2.1.0, and
[CLI and output](/sprawl-guard/reference/cli-and-output/) lists its rule IDs.
