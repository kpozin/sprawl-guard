## The executable was not found

Check the installation for your package manager:

## Configuration is missing or invalid

Sprawl Guard uses built-in defaults when neither `sprawl-guard.toml` nor `.sprawlrc.toml` exists.
Run `sprawl-guard init --dry-run` to preview a configuration. If both files exist, remove one or
select one with `--config PATH`. Parse errors reject unknown fields and identify the file and
location.

## No files were checked, or the check passed unexpectedly

Run `sprawl-guard languages --detected`, then inspect enabled languages, global excludes, ignore
settings, and language globs in `sprawl-guard config resolved`. `sprawl-guard explain PATH` reports
the first decision that included or excluded a path.

## A path has the wrong language, test status, or override

Use `sprawl-guard explain PATH`. It reports language ownership, production or test classification,
effective limits, matching overrides, and Rust `cfg(test)` handling. Overlapping language includes
can make ownership ambiguous; later matching overrides win for fields they set.

## A baseline entry is stale, missing, or conflicted

A stale entry means that a measurement improved, disappeared, or no longer exceeds its configured
limit. Preview `sprawl-guard ratchet PATH`, then write it with `sprawl-guard ratchet PATH --write`.

If a current violation has no entry, preview `sprawl-guard baseline PATH`, then write it with
`sprawl-guard baseline PATH --write`.

After concurrent edits, update your checkout and regenerate the affected entries. Never resolve a
ratchet conflict by keeping an unexplained higher ceiling.

## Local and CI results differ

Compare the output of `sprawl-guard --version`, checkout contents, repository root, configuration
path, resolved configuration, and command line. CI should run `sprawl-guard check` without path
scopes or write flags. Ignore rules and filesystem traversal settings can also change which files
are visible.

## JSON or SARIF is rejected

Confirm that `--format json` or `--format sarif` is attached to `check`. Diagnostic commands support
human or JSON output, but not SARIF. Check the exit code before parsing stdout. Exit code `2` can
report some traversal failures as structured output, but other operational errors write
human-readable stderr and may leave stdout empty. SARIF is version 2.1.0; its rule IDs are listed in
[CLI and output](/sprawl-guard/reference/cli-and-output/).
