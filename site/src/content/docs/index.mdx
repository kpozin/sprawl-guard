Keep coding agents from adding oversized files and crowded directories. Sprawl Guard counts the
lines in each file (using [Tokei](https://github.com/XAMPPRocky/tokei)) and the source files
directly inside each directory.

Sprawl Guard supports every language bundled with Tokei, including Rust, TypeScript, JavaScript,
Python, Go, Java, Kotlin, Swift, C, and C++. Run `sprawl-guard languages` for the complete list.

## Sprawl Guard or ESLint?

If a JavaScript or TypeScript linter's file-length rule is enough, use the `max-lines` rule in
[ESLint](https://eslint.org/docs/latest/rules/max-lines) or
[Oxlint](https://oxc.rs/docs/guide/usage/linter/rules/eslint/max-lines). Choose Sprawl Guard when
you also need limits on direct files per directory, separate limits for production and test code,
existing violations that can shrink but not grow, or support for polyglot repositories.

Browse the [source](https://github.com/kpozin/sprawl-guard) and
[releases](https://github.com/kpozin/sprawl-guard/releases), or
[open an issue](https://github.com/kpozin/sprawl-guard/issues).
