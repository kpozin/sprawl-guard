Keep coding agents from adding oversized files and crowded directories. File-length limits measure
logical lines of code (LOC).

Sprawl Guard supports every language bundled with
[Tokei](https://github.com/xampprocky/tokei), including Rust, TypeScript, JavaScript, Python, Go,
Java, Kotlin, Swift, C, and C++. Run `sprawl-guard languages` for the complete list and default file
paths. Code always counts; comments and blank lines are configurable, and literate-language prose
counts by default.

## Sprawl Guard or ESLint?

If a JavaScript or TypeScript linter's file-length rule is enough, use the
`max-lines` rule in [ESLint](https://eslint.org/docs/latest/rules/max-lines) or
[Oxlint](https://oxc.rs/docs/guide/usage/linter/rules/eslint/max-lines). Choose Sprawl Guard when
you also need directory fan-out limits, separate limits for production and test code, existing
violations that can shrink but not grow, or support for polyglot repositories.

Browse the [source](https://github.com/kpozin/sprawl-guard) and
[releases](https://github.com/kpozin/sprawl-guard/releases), or
[open an issue](https://github.com/kpozin/sprawl-guard/issues).
