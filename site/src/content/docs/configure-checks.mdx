Add the sections below to `sprawl-guard.toml` at the repository root.

## Select source files

Every bundled language is enabled by default. Add a `[languages.<id>]` section only to customize or
disable it. Language IDs are case-insensitive; use `sprawl-guard languages` to see accepted keys and
bundled paths.

```toml title="sprawl-guard.toml"
[languages.rust]
enabled = false

[languages.typescript]
include = ["src/**/*.ts"]
additional_globs = ["generated/**/*.ts"]
exclude = ["src/generated/**"]
```

`[files].exclude` removes paths before language classification. `include` replaces a language's
bundled paths, `additional_globs` extends them, and `exclude` removes matching candidates. Avoid
overlapping matches: a file owned by more than one enabled language is ambiguous.

## Set limits and classify tests

```toml title="sprawl-guard.toml"
[limits.max_lines_per_file]
included_line_types = ["code"]
production = 400
test = 800

[limits.max_leaf_files_per_directory]
production = 8
test = "unlimited"

[tests]
check_path_tests = true
globs = ["tests/**", "**/*.test.*"]
```

Global and language-specific test globs classify whole files as test code. Test files use the `test`
limits; production files use `production`. File limits count the selected line types. Literate
languages include comments automatically, so Markdown prose counts by default; a language-specific
`included_line_types` value can replace that behavior. Setting `check_path_tests` to `false` omits
path-classified tests. For production Rust files, Sprawl Guard can also exclude top-level
`cfg(test)` items from configured LOC.

## Add overrides

Overrides apply in declaration order. Each matching override changes only the limit fields it
sets, so a later match wins for those fields.

```toml title="sprawl-guard.toml"
[[overrides]]
paths = ["src/legacy/**"]
max_lines_per_file = { production = 1000 }
reason = "Legacy subsystem"

[[overrides]]
paths = ["src/legacy/small/**"]
max_lines_per_file = { production = 500 }
reason = "Smaller legacy modules"
```
