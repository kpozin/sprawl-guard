Every root configuration starts with its editor schema and schema version:

```toml title="sprawl-guard.toml"
#:schema https://kpozin.github.io/sprawl-guard/schemas/v2/sprawl-guard.schema.json
schema_version = 2
```

Add only the sections needed to change the built-in defaults.

## Select source files

Every bundled language is enabled by default. Add a `[languages.<id>]` section only to customize or
disable it. Language IDs are case-insensitive; use `sprawl-guard languages` to see accepted keys and
bundled paths.

```toml title="sprawl-guard.toml"
[languages.rust]
enabled = false

[languages.typescript]
include = ["src/**/*.ts"]
extend_include = ["generated/**/*.ts"]
exclude = ["src/generated/**"]
```

`[files].extend_exclude` removes paths before any language claims them. `include` replaces a
language's bundled paths, `extend_include` extends them, and `exclude` removes matching paths from
that language. A file that more than one enabled language claims is an error; disable one language
or narrow its paths.

## Set limits and classify tests

```toml title="sprawl-guard.toml"
[limits.max_lines_per_file]
count_lines = []
production = 400
test = 800

[limits.max_direct_files_per_directory]
production = 10
test = 10

[tests]
check = true
globs = ["tests/**", "**/*.test.*"]
```

A file that matches a global or language-specific test glob is a test file. Test files use the
`test` limits, and production files use `production`. Setting `[tests].check` to `false` skips test
files.

Code lines always count, and `count_lines` adds comments or blank lines. In literate languages such
as Markdown, Sprawl Guard also counts comments, so prose counts by default. A language-specific
`count_lines` value replaces this.

For production Rust files, Sprawl Guard can also stop counting top-level `cfg(test)` items.

## Group related languages for directory limits

Languages outside custom groups share the automatic `source` group's direct-file count. Literate
languages such as Markdown go to the `documentation` group, which is unlimited by default. Define a
custom group when a set of related languages should share its own direct-file limit:

```toml title="sprawl-guard.toml"
[language_groups.frontend]
languages = ["javascript", "typescript", "jsx", "tsx"]

[language_groups.frontend.limits.max_direct_files_per_directory]
production = 12
```

Omitted custom-group limits inherit the global values. Path overrides apply after group limits. One
override can change both file and directory limits for matching paths without naming a language
group.

## Add overrides

Overrides apply in declaration order, and each one changes only the limit fields it sets. When two
matching overrides set the same field, the later one wins.

```toml title="sprawl-guard.toml"
[[overrides]]
paths = ["src/legacy/**"]
max_lines_per_file = { production = 1000 }
reason = "Legacy subsystem"

[[overrides]]
paths = ["src/legacy/small/**"]
max_lines_per_file = { production = 500 }
reason = "Smaller legacy modules"
```
